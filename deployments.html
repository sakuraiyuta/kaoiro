kaoiro / Deployments

Deployments

Three example layouts. Host names are placeholders, and the offline example is a future concept, not something you can run today.

01 / Example A

Several on-premises hosts, split by role

The layout the author uses every day, with host names replaced by placeholders. The server, the agents and heavy tests each have a machine of their own.

  • server-host

    One Linux machine. The kaoiro server runs under Docker Compose behind an HTTPS reverse proxy and is reachable from the Internet.

  • agent-host

    One Linux machine. The runner stays resident as a systemd user unit and supervises about a dozen agents on this host: roughly 6 Claude Code, 4 Codex, 2 Antigravity and 1 Grok Build.

  • test-host

    A separate machine that runs heavy tests in isolated containers. This is the author's own arrangement, not a kaoiro feature.

  • Clients and files

    The operator uses the dashboard in a browser on a PC and on a phone. Files for the operator to read are passed through a self-hosted Nextcloud, also outside kaoiro.

Each engine needs an account with its vendor; see Getting started. An operator credential lets its holder run commands on agent-host, so read SECURITY.md before you expose a server.

02 / Example B

Everything on one machine

For one person, the server, a runner and the agents can share a single host. You follow the same runbooks as for several hosts, on one machine.

  • Where it runs

    One machine runs the server under Docker Compose, a runner, and the agents you launch. By default the server binds only to 127.0.0.1:4000 and a reverse proxy on the same host reaches it.

  • Answering from a phone

    Decide how the server is reached before writing .env: an HTTPS reverse proxy, or a direct address inside a VPN that must never be exposed to the public Internet. Both are in the network and login runbook.

  • Trying it first

    The README's Quick start starts every layer on one machine with ./scripts/dev.sh, with hot reload. For daily use, follow the production manual.

  • Keep in mind

    Restarting a runner stops every agent beneath it. With one host, every agent you run is beneath that runner.

03 / Example C

Offline, inside an intranet: a future concept

Not possible today. kaoiro does not support local AI agents yet. This section describes how it could work if that support arrives. Do not plan a deployment around it.

Claude Code, Codex, Antigravity and Grok Build all rely on their vendors' cloud services, so kaoiro cannot run cut off from the Internet today.

  • What would have to change

    An engine that runs a model on your own hardware. Issue 1043 proposes making engines pluggable, so that an external engine could connect over a public protocol instead of being added to the source. It is an open proposal with no release date.

  • What could stay inside

    The server, the runners and the dashboard already run on your own machines. With such an engine, the whole set could in principle stay inside the intranet.
