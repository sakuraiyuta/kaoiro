Research prototype. Developed mainly for daily use by the author and members of their laboratory, with no guarantees about maintenance or responses to issues.

Security. An operator credential lets its holder run commands on every machine where agents run. Treat it like an SSH key to those hosts, and read SECURITY.md before deploying.

State as a face

kaoiro runs, watches and orchestrates several CLI AI agents at once. Each one becomes a character whose expression follows what it is doing, so running a few agents feels closer to keeping a small virtual AI office than to cycling through terminals.

thinking

From engine events, not guesses

Each agent's state is derived from engine events and drawn as an expression. It is not inferred from the text the agent writes.

idle

Quiet is visible too

Every running agent keeps its own card, character and state label, with a name that persists across sessions.

See who needs you

A badge marks the agent waiting on an answer. The permission request comes to the browser, so it never blocks on an unattended terminal.

The whole office at a glance

The timeline beside the grid merges what every agent said with the messages they send each other.

One screen for every agent

Everything below is in the dashboard today. kaoiro is open source under the MIT License.

  • Launch from the browser

    Choose host, persona, engine, working directory and permission mode, then stop, restart, restore or resume a session.

  • Approve in the UI

    A tool call waiting for approval is routed to the client. Multiple-choice questions arrive as dialogs on the same path.

  • Agents message each other

    A delegation, a review request or an approval between agents is a first-class message, grouped into conversations.

  • One merged timeline

    Replies and agent-to-agent messages sit in a single time-ordered pane, with unread marks and click-through to the transcript.

  • Personas as zip packs

    Characters are versioned, hash-checked packs read from an ingest directory, with a bundled set as the default.

  • Notifications

    A desktop notification and a per-state sound tell you when an agent hands control back.

Four engines, working together

kaoiro supports Claude Code, Codex, Antigravity and Grok Build, and you choose the engine at launch. A message from an agent on one engine reaches an agent on another, so they can delegate, review and answer each other in the same conversation.

  • Claude Code

    Hosted through the Claude Agent SDK.

  • Codex

    Hosted through the Codex app-server.

  • Antigravity

    Hosted through the Antigravity CLI.

  • Grok Build

    Hosted as one resident ACP session.

Engines are not identical. Model and effort switching, permission modes and file uploads depend on what each engine declares, and whether a message can reach a running turn differs by engine. The dashboard follows those declared capabilities.

How you might use it

A few ways the features fit together. These describe the work kaoiro carries, not a promise about results.

  • Run agents side by side

    Give several agents their own tasks and working directories, then watch the grid instead of cycling through terminals.

  • Split implementation and review

    One agent implements and another reviews. The hand-off is a visible message, such as a request to review a diff, without opening anyone.

  • Answer from another device

    The dashboard has a layout that collapses down to a phone, so you can answer a waiting agent away from your desk, on a deployment you can reach from there.

Separate parts, many hosts

kaoiro is split into four parts with clear roles. One server can gather agents from several machines, each supervised by its own runner.

  • Server

    Aggregates wrappers, keeps their state, delivers it to clients in real time and routes instructions to the right agent.

  • Runner

    One per host. It spawns, stops and restarts wrappers and registers the host, and it stays out of the data path.

  • Wrapper

    Launches an agent and translates engine-specific events into a common format. Wrappers connect directly to the server.

  • Client

    Shows each agent as a character. The bundled web dashboard is one client.

Room to extend

Because the parts are separate, you can change one without rewriting the others.

  • Build your own client

    The server and client talk over a documented public protocol. The bundled dashboard is the reference implementation and uses the same protocol, so another client can be built on it.

  • Add an engine in the source

    Each engine has its own wrapper package on a shared core. Adding one means changing the source, including the engine lists in the runner and the server. Grok Build was added this way.
