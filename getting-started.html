kaoiro / Getting started

Getting started

From the account each engine needs to the first agent on your screen, and what running it looks like after that.

01 / Overview

The path, in order

Security. An operator credential lets its holder run commands on every machine where agents run. Treat it like an SSH key to those hosts, and read SECURITY.md first.

  1. Arrange an account for each engine you will use
  2. Prepare the hosts
  3. Install the server
  4. Install a runner on each agent host
  5. Launch your first agent
  6. Run it day to day

This page is a map. The commands and their exact order live in the repository docs, and when this page and the docs differ, the docs win. Start from the production manual.

02 / Accounts

03 / Hosts

Prepare the hosts

Decide which machine runs the server and which run agents.
They can be the same machine (example B).

  • Server host

    Docker Engine with the Docker Compose plugin, Elixir ~> 1.15 with Phoenix, and Node.js 22 or later for the deploy CLI.

  • Agent hosts

    Node.js 22 or later, and the CLI of each engine you will run there. Linux runs the runner as a systemd user unit.

  • How the server is reached

    Choose before writing .env: the default is 127.0.0.1 behind an nginx reverse proxy, and a direct address inside a VPN is the alternative.

  • Access

    SSH access to the server host and every runner host, with each host key already known.

Full list: Server install runbook, Prerequisites.

04 / Server

Install the server

  1. Clone the repository on the server host at the exact commit you intend to run.
  2. Run mix kaoiro.env in server/. It writes .env, generates SECRET_KEY_BASE and the client and runner tokens, and asks for the public host name. Keep the runner token it prints for the runner step.
  3. Start it with node server/deploy/kaoiro-server-deploy.mjs start --initialize from the checkout root.
  4. Set up the reverse proxy or the VPN address, and optionally Google, GitHub or Nextcloud login, from the network and login runbook.

Detail: Server install runbook and production manual, section 1.

05 / Runner

Install a runner on each agent host

  1. Build the runner tarball for the host's OS and CPU, and copy it to the host.
  2. Run kaoiro-runner-bootstrap.sh from the unpacked tarball. Its wizard is the only interactive step; it then installs the runner and starts it as a service.
  3. On Linux, enable lingering for the user so the runner starts at boot without a login.
  4. Install each engine's CLI on the host and sign it in as the user the runner runs as. Production Codex uses a dedicated home directory; see Codex home for production.

Detail: Runner install and distribution and production manual, section 2. Check the result with section 3, Verify.

06 / Launch

Launch your first agent

  • Sign in

    Open the dashboard and sign in with a client token or with the login you configured.

  • Launch

    Choose host, persona, engine, working directory and permission mode, and start the agent. The working directory has to be one the runner allows.

  • Watch and answer

    The agent appears as a character card. A tool call waiting for approval comes to the browser, and you answer it there.

07 / Daily

Run it day to day

  • Approvals and notifications

    A desktop notification and a per-state sound tell you when an agent hands control back. The dashboard collapses down to a phone, so you can answer away from your desk.

  • Updates and rollback

    Server and runner updates have their own order. Take it from the production manual, section 4, and roll back with section 5. Restarting a runner stops every agent beneath it.

    Start from deployment troubleshooting.
