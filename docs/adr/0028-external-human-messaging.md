## Decision

### D1:   transport

transport is a trans  (agent ↔ external human), authority is one-way. external human
Destructive/non-destructive/exa  agent behavior**No drive**Home Home
The input is notified to the operator and the execution judgment is generated by the operator and the agent itself
Only belongs to the content. This is the core security nature of this function.

### D2: discord-wrapper topology ( broker is firmly brokered)

Discord connection is retained by dedicated discord-wrapper(ex) channel adapter entity).
Close bot  there. server only routes with `to`
Contact Us wrapper(agent), client(operator), wrapper
Keep the principles and reuse existing inter-agent routing / observation /  ta.

### D3: route separation with dedicated type tools

untrusted-ex  route trusted-agent route and**Code separation**For
`external_message` new type and `send_to_human` tool (inter-agent)
not generalized). If trust model is in one route, the condition is leaked immediately
To become a vulnerability.

### D4: outbound = whitelist

The destination is only within the whitelist that the operator creates in the config file. enforce
discord-wrapper. The agent only discloses the logical contact id + display name.
Discord ID / PII keeps in the wrapper (list disclosure does not weaken the defense — enforce
collateral, office meta s). send to `permission_broker` and send to + body
Approve each time The external man expresses AI/kaoiro.

### D5: inbound = Tier A (Default) / Tier B (Safetyke gate)

- **Tier A**(phase-0): Fixed temporal reply without LLM + original text to operator
verbatim Relay. Injection Surface Zero. fail-soft.
- **Tier B**(phase-1): separation of "transmitting agent with tools"
  **zero-tool**`ext.interpretation`
grant (the first application of the plugin-model filter mechanism),
responder generates a limited reply. Non-injected to working agent. atim
