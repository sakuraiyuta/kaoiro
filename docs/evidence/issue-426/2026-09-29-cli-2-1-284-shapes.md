# Claude CLI 2.1.284 background-task shapes

## Verdict and decision boundary

**Hand-back shape: unmeasured on 2.1.284.** The five permitted root runs did
not produce a child `PreToolUse:SubagentHandback` or root `<agent-message>`.
This does not establish a version regression: the retained 0.3.280 sanitized
query also produced neither. The successful historical hand-back runs used a
different composition and live model behavior.

**Task notifications: observed.** The streaming host composition produced
one-Agent, four-Agent and background-Bash notification frames, root hooks and
`task-notification` terminal origins. The task/parent-tool identities and
notification grammar described below are established for those runs. Full
byte equivalence across versions, repeated-task behavior, hand-back terminal
identity, and all possible interleavings remain unmeasured.

The director explicitly keeps [issue #426](https://github.com/sakuraiyuta/kaoiro/issues/426) admission frozen and fail-closed.
The planned phase-2 canary's safety does not depend on obtaining a positive
hand-back observation here. This is the director's scope decision, not a
safety claim derived from an absent event; no frozen guard was changed.

## Fixed artifacts and observation boundary

Baseline: `69a474526b2dfe538aa14be8aa8a5b703c00da1d`, SDK 0.3.284, bundled

## Notification shape and identity

Counts copied from `handback-measurements.json` and raw native records:

| Run | Requests | task_started | task_notification | Notification root hooks | Hand-back hooks / roots | Result indices |
| --- | --- | --- | --- | --- | --- | --- |
| N1 | 5 | 1 | 1 | 1 | 0 / 0 | 0, 1 |
| N2 | 14 | 4 | 4 | 4 | 0 / 0 | 0, 1, 2, 3, 4 |
| N3 | 3 | 1 | 1 | 1 | 0 / 0 | 0, 1 |

For every task, the native `task_started.tool_use_id` equals the root parent
PreToolUse ID. The notification hook carries the same task ID and parent
tool-use ID, the initial session ID, and a fresh prompt ID. Index 0 is
originless; all later results have `origin.kind=task-notification` and
`producer=session-task`. The current `producer` field is observed; its
absence from a prior summarized recorder is not proof it was newly introduced.

Example N1:

- Task: `ac60fa7381657b9a5`.
- Parent tool use: `toolu_a96475ad0c0248928a899e4c0a3ab783`.
- Initial prompt: `c6c23fe4-82cf-4096-af88-8facfc9b813e`.
- Notification prompt: `7a6c7265-eba6-4900-9df0-0592627ebb35`.
- Session: `4d72276f-faa5-4b3e-8c11-05bb9baa9f3d`.

Agent root text uses `<task-notification>` with `<task-id>`, `<tool-use-id>`,
`<output-file>`, `<status>completed</status>`, `<summary>`, the repeated-task
`<note>`, `<result>` and `<usage>`. The note says that a resumed task can notify
again with the same ID; this run does not exercise that behavior. Bash uses
the same task/parent/output/status/summary fields, without the Agent result,
usage or note. Exact examples are retained as `N1.notification-example.txt`
and `N3.notification-example.txt`.

## Controls, limits and cleanup

N3 is the native no-hand-back background-Bash control. The checker also
replaces the task's parent tool-use ID in the observed hook in memory while
leaving its SDK task record unchanged: exit 1. Restoring unchanged raw input
returns exit 0. Raw evidence is never rewritten by this negative control.
No fabricated hook or result substitutes for an unavailable positive case.

All five hand-back allocations were consumed. All invocations exited 0, but
none establishes hand-back availability. N1/N2/N3 lasted 3745/5929/2268 ms;
the entire first batch used 12/16 root runs and a 623.087-second SDK window.
All recorded SDK children exited; owned listeners, scratch worktree and task
output roots were cleaned up. The exact cleanup and retained evidence are
listed in the linked batch report and `cleanup.json`.
