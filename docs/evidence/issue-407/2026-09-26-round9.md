# Channel lifecycle verification

The round-eight finding was a nonterminating send after `phx_close`: Phoenix
removes that channel without scheduling rejoin, while the wrapper waited for a
future join. The [follow-up design](../plans/issue-407-rejoin-followup.md#channelsocket-lifecycle-contract)
now defines the complete channel/socket transition table, including finite
negotiation and CID waits, generation invalidation, and automatic rejoin rules.

## Contract and permanent controls

Terminal channel close, normal socket close, and explicit ServerLink close
release current/future negotiation waiters with `closed`. Tool calls return
`reply_basis_closed` and `send_not_attempted: true`, without renewed tickets.
Recoverable errors invalidate the generation and await rejoin; join error/timeout
releases current waits as failed. Each wait has a fixed ten-second ceiling.
Failed waits retain their result even when rejoin succeeds before their
continuations. Internal notices also refuse those failed waits, with a definite
no-send diagnostic. Already-written pushes retain acknowledgement/unknown
semantics; neither sends nor notices are automatically retried.

`wrapper/codex/test/reply_basis_lifecycle.test.ts` contains 22 permanent controls:

- Initial v1 and legacy join; channel error and close; abnormal and normal socket
  close; socket error; join error and timeout; local channel leave; server
  channel stop/revoke; unrecognized application `leave`/`kick`; explicit link
  close; caller abort; and a silent join's fixed deadline.
- Direct negotiation waits and same-CID calls, including queued successors.
  The silent-join control observes two successive ten-second waits draining.
- A failed wait held past a later successful join; recoverable ticket renewal
  versus terminal no-renewal; provisional authorization before/after result
  handoff; internal notice outcomes; and a written push becoming unknown while
  its queued successor is rejected locally.

These use actual ServerLink, InterAgentTool, Phoenix 1.8.8, and a loopback
WebSocket peer. Most controls shorten Phoenix timers; the default-construction
`phx_close` case injects no socket factory. The fixed deadline test uses real
time. Socket error uses the actual WebSocket EventTarget. The server's revoke
handler was read directly; the test supplies its `phx_close` wire outcome rather
than starting another Elixir server. The existing join/rejoin suite still covers
held network acknowledgements, legacy-to-v1 changes, and old-generation refusal.
