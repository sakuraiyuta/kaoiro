# Claude Agent SDK 0.3.284 rollout observations

Measurements were taken on 2026-09-29 in `worktrees/momo-427`. The wrapper
dependency changed from `@anthropic-ai/claude-agent-sdk` 0.3.280 (bundled CLI
2.1.280) to 0.3.284 (CLI 2.1.284). `npm view` reported version 0.3.284 and
`claudeCodeVersion` 2.1.284. No external model API was called by the catalog
probes or host input capture. The resolved SDK entry `sdk.mjs` has SHA-256
`32d062c37b03e10870fbf839f54694545ee01bc0ec719e47078fbed76e30ef71`.

## Catalog probes

The direct probe used `wrapper/claude-code/dist/probe.js` and returned
`ok: true`, `source: "init"`. The catalog mapping for the requested values was:

| Requested value | SDK 0.3.280 `resolved_model` | SDK 0.3.284 result |
|---|---|---|
| `default` | `claude-opus-5-5[1m]` | `claude-opus-5-5` |
| `opus[1m]` | `claude-opus-5-5[1m]` | No exact row; init and context usage reported `claude-opus-5-5[1m]` |
| `claude-fable-5-1[1m]` | `claude-fable-5-1` | Exact pinned row resolves to `claude-fable-5-1`; init and context usage retain the suffix |
| `sonnet` | `claude-sonnet-5` | `claude-sonnet-5-5` |
| `haiku` | `claude-haiku-4-5-20251001` | `claude-haiku-4-5-20251001` |

The 0.3.284 default probe returned 12 rows. With `Options.model: "opus[1m]"`,
the SDK returned the same 12 rows and omitted an exact `opus[1m]` row. The raw
`init.models` fixture is
[`claude-agent-sdk-0.3.284-opus-1m.models.json`](../../../../wrapper/claude-code/test/fixtures/claude-agent-sdk-0.3.284-opus-1m.models.json),
SHA-256 `b1f649a21e14e58e516375b6cbcbc511e574ca19fa084a6725d4bfb9d3b86fe7`.
The fixture shows the alias row `opus` has a `resolvedModel` different from its
`value`; the canonical `claude-opus-5` row is self-resolving. A query pinned to
`claude-opus-5[1m]` returned no exact row, so the host does not treat that
canonical ID as the base alias.

SDK 0.3.280 queries pinned to `opus[1m]` and `opus` both exposed effort levels
`low`, `medium`, `high`, `xhigh`, and `max`. The 0.3.284 base `opus` row exposed
the same five levels.

The `.284` init and context reports for `opus[1m]` were captured with a
loopback-only API stub. A separate request capture by Kogane, relayed by the
director in [issue #427](https://github.com/sakuraiyuta/kaoiro/issues/427),
observed `model: "claude-opus-5-5"` for both the `opus[1m]` and `opus` options,
with the `context-1m-2025-08-07` `anthropic-beta` value only on the suffixed
request. Setting `CLAUDE_CODE_DISABLE_1M_CONTEXT=1` removed that value. This
records the outgoing request option; it does not establish provider acceptance.

The fixture and request capture show why the wrapper keeps the persisted and
sent value `opus[1m]` while consulting the base alias row only for metadata.
Model comparison requires an exact lowercase `[1m]` suffix on both the pin and
reported model; a missing suffix or a different base ID remains a fallback.
Only the exact lowercase suffix is recognized.

## Agent instructions and state projection

An AGENTS-only scratch project was started through the real Claude host and
SDK 0.3.284 with the host's default query options; the host does not set
`settingSources`. The scratch directory contained only `AGENTS.md` with a
non-secret marker. A loopback API endpoint captured the first request. The
marker appeared in the request's `messages` content, not its `system` field.
The request stayed on loopback and the scratch directory was removed after
capture. This verifies that the instruction reached the outgoing model input;
it does not establish how a remote provider would use it. The same host query
included the wrapper-installed `UserPromptSubmit` hook, which returned `{}`,
and proceeded to the captured request. This is a compatibility observation
for that SDK run, not an exhaustive hook contract.

The scripted Sonnet 5.5 adapter test substitutes a `thinking` block for a
`text` block between the same tool events. Both inputs produce the same coarse
state trace; the thinking block is not emitted as a transcript log. This is a
mapping test, not a measurement that a live Sonnet 5.5 response emits either
content-block shape.

## Claims retained from SDK 0.3.280

The Claude child shutdown timings and `AbortError` behavior remain recorded as
0.3.280 measurements and were not remeasured on 0.3.284. The SDK error-pipe
observation is likewise versioned as 0.3.280. The prompt-generator return
observation in `wrapper/claude-code/src/host.ts` is also limited to 0.3.280;
it was not remeasured on 0.3.284. Dated evidence files predating this rollout
were left unchanged.
