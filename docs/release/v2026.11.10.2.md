# Release v2026.11.10.2

- Previous production release: [v2026.11.10.1](v2026.11.10.1.md)
- Range: `v2026.11.10.1..v2026.11.10.2`
- Release class: TL
  ([High-risk change release](../operations/high-risk-change-release.md)).
  The TL path list catches `wrapper/core/src/transport.ts`,
  `wrapper/agent-common/src/inter_agent.ts` and
  `wrapper/claude-code/src/host.ts`, so every engine is affected. No file on
  the FS path list changes and no engine SDK, CLI or native pin changes.

## Highlights

- **Rooms.** An agent is in exactly one room, and the server accepts
  `send_to_agent` only between agents in the same room. Every agent starts in
  the lobby, so with no room in use messaging behaves as before. The operator
  creates, renames and deletes rooms and moves agents on the dashboard
  ([rooms](../reference/inter-agent/rooms.md),
  [ADR-0072](../adr/0072-rooms-single-membership-send-boundary.md),
  [issue #537](https://github.com/sakuraiyuta/kaoiro/issues/537),
  [issue #1059](https://github.com/sakuraiyuta/kaoiro/issues/1059),
  [issue #1060](https://github.com/sakuraiyuta/kaoiro/issues/1060)).
- **A long background-command label no longer loses the continuation
  proof.** The regression listed in the previous release is fixed for Bash
  and Monitor completions
  ([issue #1068](https://github.com/sakuraiyuta/kaoiro/issues/1068)).

## Changes

### Server and protocol

- A new DETS store `rooms` (`KAOIRO_ROOMS_PATH`) holds the rooms and the
  memberships. The bundled compose places it at `/var/lib/kaoiro/rooms.dets`
  on the state volume ([server configuration](../reference/configuration/server.md)).
- The server refuses a message whose sender and recipient are in different
  rooms with `room_mismatch`, both in the wrapper channel and when the
  conversation records the message. Server notices, operator instructions and
  history replay are not subject to the rule.
- Moving an agent or deleting a room closes every open conversation it
  splits, with reason `room_changed` or `room_deleted`. Work items are not
  cancelled or reassigned. A connected agent that is moved receives a
  `room_changed` server status notice that asks for no reply.
- `list_agents` entries and `whoami` carry `room` (`{id, name}`, `name: null`
  for the unrenamed lobby). An absent `room` means unknown, not the lobby.
- Six operator-only dashboard channel requests manage rooms: `create_room`,
  `rename_room`, `delete_room`, `move_agent`, `preview_room_move` and
  `preview_room_delete` ([channel events](../reference/protocol/channels.md)).

### Wrappers

- All engines read `room` into `list_agents` and `whoami`, explain a
  `room_mismatch` refusal to the model, and inject a `room_changed` notice as
  a status notice without opening a conversation track.
- Claude Code: the continuation proof accepts a completion summary in the
  CLI's shortened form (a summary over 1,000 UTF-16 units keeps its first 500
  and last 300, escaped after shortening). The Monitor description check runs
  against the SDK summary. The rule and its measurements are in the
  [Claude events reference](../reference/engines/claude-events.md) and the
  [evidence](../evidence/claude/issue-1068/shortened-completion-summary-2026-11-10.md).

### Dashboard

- Once the server's room snapshot arrives, the agent grid is split by room:
  the lobby first, then the other rooms, each with its name and tile count.
  The operator sees "Create room", rename and delete on each room and
  "Change room" on each tile. A move or delete first shows how many
  conversations it would close. A viewer sees the room separators and no
  control; an agent whose room a viewer's snapshot does not confirm is listed
  under "room not confirmed"
  ([dashboard design](../reference/ui/design.md)).

## Operator steps

- Update the server and the runner to the same commit, the server while the
  runner is stopped. A wrapper of either release works with a server of
  either release while no agent is moved: an older server sends no `room`,
  which reads as unknown.
- The update stops at the persistence-path check because `KAOIRO_ROOMS_PATH`
  is a store the previous image does not have. Establish that it is new (no
  earlier release had a rooms store) and resume the same transaction with
  `--accept-new-store KAOIRO_ROOMS_PATH`
  ([Server update and rollback 4.3](../operations/server-update-and-rollback.md)).
- The server creates `rooms.dets` (mode 0600) on the state volume when it
  first starts. It starts empty: every agent is in the lobby.
- The release is TL for every engine. Run the start gate (recommended for
  TL), then follow
  [Release and restore the fleet](../operations/high-risk-change-release.md#4-release-and-restore-the-fleet).
  After restoration, check one turn on a peer of each engine in use.
- No new runner setting. The persona packs do not change.

## Rollback

- Roll the server and the runner back to v2026.11.10.1 with the usual
  procedures. A server rollback after the new server has started is the
  destructive restore of the pre-deploy archive, which has no `rooms.dets`:
  rooms and memberships are lost, and the previous server knows no rooms.
- Rolling back only the runner leaves the rooms enforced by the server.
  Older wrappers do not show `room` and do not recognise the `room_changed`
  notice, so do not move agents while the runner is on the previous release.
- The Claude Code fix goes away with the runner rollback, and the regression
  of v2026.11.10.1 returns.

## Known limits

- Rooms Phase 0 has no paging: an agent that the dashboard does not list
  cannot be moved from it. Users are not members of a room.
- An agent cannot complete or cancel a work item across rooms; the
  operator's work controls on the dashboard still can.
- After `room_change_unconfirmed`, reload the dashboard to read the rooms
  again. The dashboard does not reload by itself.
- The shortened-summary rule is measured for Bash and Monitor completions
  only. Workflow, failed and stopped completions are not measured, and any
  other shape is still refused with `native_completion_unproved`.
