# Release v2026.11.06.1

- Previous production release: [v2026.11.05.1](v2026.11.05.1.md)
- Range: `v2026.11.05.1..v2026.11.06.1`
- Release class: FS and TL
  ([High-risk change release](../operations/high-risk-change-release.md)).
  `runner/src/supervisor.ts`, `runner/src/runner-cli.ts`,
  `runner/src/delivery-settings.ts`, `wrapper/core/src/transport.ts` and the
  `host.ts` and `cli.ts` of every wrapper changed.

## Highlights

- **Codex launches default to app-server.** A launch selects app-server when
  `codex.backend` is omitted. Explicit `exec` remains available
  ([issue #564](https://github.com/sakuraiyuta/kaoiro/issues/564)).
- **The Claude delivery opt-in is retired.** Claude resolves to fold, fold and
  tool boundary when the ceiling permits. The old flag, persona list and file
  key stay recognized only to warn
  ([issue #565](https://github.com/sakuraiyuta/kaoiro/issues/565)).
- **Compaction no longer fail-stops a busy Claude peer.** A resume note now has
  its own bounded admission, so a notification or peer message that queues
  during `/compact` no longer stops the wrapper
  ([issue #991](https://github.com/sakuraiyuta/kaoiro/issues/991)).
- **The permission-sync wait has a deadline.** A wrapper that negotiates
  `permission_sync` fails the input after 30 seconds instead of waiting forever
  ([issue #673](https://github.com/sakuraiyuta/kaoiro/issues/673)).

## Changes

### Codex

- The maintenance CLI adds a read-only `observe` phase and operator-run
  `remove-pin`, `pin-exec-fresh` and `restore-fresh` phases. Each uses a newly
  observed record accepted by the operator, and checks the runner identity,
  routing, host inventory and Supervisor work
  ([issue #564](https://github.com/sakuraiyuta/kaoiro/issues/564)).
- The app-server default was not measured with API-key authentication. If you
  use API-key auth and need the previous behavior, set `codex.backend` to
  `exec`. If the host already has app-server sessions, follow the guarded fresh
  transition in the [migration runbook](../operations/codex-backend-switch.md)
  first; selecting exec does not authorize resuming existing app-server IDs
  through exec.

### Delivery and wrappers

- A resume note has its own bounded receipt. While it is pending, peer and
  operator input waits for at most the watchdog `inactivityMs`, then the host
  fail-stops with reason `starved`. Under continuous notifications the note is
  not guaranteed to arrive
  ([issue #991](https://github.com/sakuraiyuta/kaoiro/issues/991)).
- On a permission-sync timeout the affected input fails, and a disconnected
  wrapper keeps the latest error result and sends it once after rejoin. Claude
  Code and non-Linux Grok do not negotiate `permission_sync` and have no such
  deadline ([issue #673](https://github.com/sakuraiyuta/kaoiro/issues/673)).
- Antigravity selects the model's own quota group: Argon models read the Argon
  group, which has a weekly window only. A failed turn on a different group
  creates no overlay, and the reset seconds stay in the error
  ([issue #788](https://github.com/sakuraiyuta/kaoiro/issues/788)).
- The Antigravity stale customization sweep rejects non-positive and invalid
  marker PIDs ([issue #546](https://github.com/sakuraiyuta/kaoiro/issues/546)).

### Server

- A permission-gate envelope stays whole in an over-budget join snapshot, or the
  snapshot is marked incomplete
  ([issue #613](https://github.com/sakuraiyuta/kaoiro/issues/613)).
- Persona packs: `sprite_set: default` is rejected. When packs with different
  IDs share a `sprite_set`, the pack with the first ID in byte order stays and
  the others stop being offered. Duplicate IDs still resolve by ZIP filename
  order. Operators see the warning in the host snapshot and the launch dialog
  ([issue #499](https://github.com/sakuraiyuta/kaoiro/issues/499)).
- assent 0.3.2 and Bandit 1.14.1
  ([issue #973](https://github.com/sakuraiyuta/kaoiro/issues/973)).

### Deploy

- A destructive rollback no longer refuses every container that has a bind
  mount. Empty mount types and empty volume names are now refused
  ([issue #975](https://github.com/sakuraiyuta/kaoiro/issues/975)).
- The four `rollback_*` phases are a permanent automatic-resume refusal pointing
  to a phase-specific manual recovery block. A finished transaction moves to
  `<backup_root>/.quarantine/<tx>`, which is evidence only
  ([issue #695](https://github.com/sakuraiyuta/kaoiro/issues/695)).

## Operator steps

- This release must deploy server and runner together. **Stop every runner
  before the server commit** and follow
  [Coordinated server and wrapper updates](../operations/runner-update-and-rollback.md#coordinated-server-and-wrapper-updates).
  Then use the start gate and bulk restoration from
  [High-risk change release](../operations/high-risk-change-release.md).
- **Codex:** a host retaining an observed, applied explicit `codex.backend`
  needs no preparation; keep that setting during deployment. A host that omits
  it must install the preparation release and complete protected-exec
  preparation before this release. Unknown creation origin blocks automatic
  cross-backend migration. See the
  [migration runbook](../operations/codex-backend-switch.md).
- **Claude delivery:** inventory each runner's file and actual environment,
  direct launches, ceiling and stored per-agent policy before deployment. Stop
  on unknown or missing inventory. Keep the old settings and their values
  through the rollback window, even though the warnings say they have no effect
  ([server update](../operations/server-update-and-rollback.md#claude-delivery-opt-in-retirement)).
- **Persona overlay:** confirm that no pack in an overlay shares a `sprite_set`
  with another pack or uses `default`. The losing pack stops being offered.
- No new environment variable, no new server store and no stored format change.

## Rollback

- Rolling back #565 alone restores the earlier wrapper and runner code on top of
  #564. Reverting #564 as well is a separate rollback that needs the
  [Codex backend preparation](../operations/codex-backend-switch.md#backend-selection-and-code-rollback).
- Explicit backend selection does not protect against native-state
  incompatibility. Keep the same-native and state-aware rollback requirements.

## Known limits

- Codex exec retirement is a separate unit and needs #564 in production first.
- The Grok `permission_switch.test.ts` wait failed once in CI and passed on a job
  rerun; the cause is unconfirmed
  ([issue #673](https://github.com/sakuraiyuta/kaoiro/issues/673)).
- Grok wrappers show `work_control` but cannot accept an assignment.
- An Antigravity input sent after the agy process exited on its own can still
  fail as `api_error`, and it waits while a descendant holds stdout open
  ([issue #602](https://github.com/sakuraiyuta/kaoiro/issues/602)).
