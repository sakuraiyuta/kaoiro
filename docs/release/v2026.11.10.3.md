# Release v2026.11.10.3

- Previous production release: [v2026.11.10.2](v2026.11.10.2.md)
- Range: `v2026.11.10.2..v2026.11.10.3`
- Release class: TL
  ([High-risk change release](../operations/high-risk-change-release.md)).
  The TL path list catches `wrapper/core/src/transport.ts`, where two words
  join the closed reply vocabulary of `request_peer_session_reset`, so every
  engine is affected. No file on the FS path list changes and no engine SDK,
  CLI or native pin changes.

## Highlights

- **A new agent starts in the room the operator picks.** The launch dialog
  offers a room, and the server saves the membership before the runner is
  told, so the new agent never sees the lobby first
  ([ADR-0073](../adr/0073-initial-room-at-launch.md),
  [issue #1081](https://github.com/sakuraiyuta/kaoiro/issues/1081)).
- **A director's peer session reset stays within its room.** The server
  refuses a cross-room `request_peer_session_reset` with `room_mismatch`
  ([issue #1078](https://github.com/sakuraiyuta/kaoiro/issues/1078)).
- **Agent details on the dashboard.** The ctx and rate-limit gauges and the
  status line stay in a pinned area
  ([issue #1074](https://github.com/sakuraiyuta/kaoiro/issues/1074)), and the
  detail area is split into an engine tab and a kaoiro tab
  ([issue #1075](https://github.com/sakuraiyuta/kaoiro/issues/1075)). The
  settings drawer is grouped into tabs
  ([issue #1076](https://github.com/sakuraiyuta/kaoiro/issues/1076)).

## Changes

### Server and protocol

- `spawn` accepts an optional `room_id`. An absent `room_id`, or one naming
  the lobby, touches no room store. A named room must exist (`unknown_room`
  otherwise, checked before anything is recorded), and a present but unusable
  value is `invalid_payload`. The membership is saved through the same path as
  a move, and a failed save refuses the launch. The ok reply carries
  `room_id` as a plain string. `room_id` never reaches the runner
  ([runner control](../reference/protocol/runner-control.md)).
- `peer_session_reset_request` checks that the director and the target are
  in the same room, after the authority checks and before the reset lock.
  The closed reply vocabulary gains `room_mismatch` and `rooms_unavailable`;
  neither is an authority failure, so the work grant stays valid
  ([ADR-0068](../adr/0068-director-requested-peer-session-reset.md),
  [rooms](../reference/inter-agent/rooms.md)).

### Wrappers

- All engines accept `room_mismatch` and `rooms_unavailable` as reasons of a
  refused `request_peer_session_reset` and tell the model what to do next.
  The tool description states the same-room rule.

### Dashboard

- The launch dialog has a room picker in both of its modes, including resume
  (which allocates a new agent id). Restoring an existing agent keeps its
  stored room.
- AgentDetail pins the ctx and rate-limit gauges and the status line: under
  the agent ID at desktop width, above the log at tablet width and on a
  desktop window 699px high or less, and above the log behind a disclosure at
  smartphone width
  ([responsive layout](../reference/ui/responsive-layout.md),
  [ADR-0052 amendment](../adr/0052-responsive-three-tier-layout.md)).
- The AgentDetail detail area has two tabs, engine and kaoiro. The last
  opened tab is one browser setting for every agent. While a notice is shown
  in the closed tab, its label carries a mark
  ([responsive reachability](../reference/ui/responsive-reachability.md)).
- The settings drawer is grouped into Display, Notifications, Operations and
  Administration tabs.

## Operator steps

- Update the server and the runner to the same commit, the server while the
  runner is stopped. There is no new server store, environment variable,
  Compose change or runner setting, and the persona packs do not change.
- The release is TL for every engine. Run the start gate (recommended for
  TL), then follow
  [Release and restore the fleet](../operations/high-risk-change-release.md#4-release-and-restore-the-fleet).
  After restoration, check one turn on a peer of each engine in use.
- Reload open dashboard pages after the server update. A page loaded from the
  previous server sends no `room_id`, so its launches land in the lobby.

## Rollback

- Roll the server and the runner back to v2026.11.10.2 with the usual
  procedures. Memberships saved by a launch into a room are in the existing
  `rooms` store, which the previous server also reads; a destructive server
  rollback restores the pre-deploy archive and loses them, as it loses any
  room change made after the update.
- Rolling back only the runner keeps the server's same-room check on the
  reset. An older wrapper reads `room_mismatch` and `rooms_unavailable` as
  `unknown_error`; nothing is changed by the refused request.

## Known limits

- A dashboard or `list_agents` may briefly show a starting agent in the lobby
  while its launch is in flight; the wrapper's own first registration is not
  affected. A refused launch can leave an identity behind, which
  `delete_agent` clears ([ADR-0073](../adr/0073-initial-room-at-launch.md)).
- Continuing a launch after a failed room snapshot notice is not covered by a
  test (ADR-0073 consequences).
