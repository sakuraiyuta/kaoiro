# Release v2026.11.01.1

- Previous production release: [v2026.10.28.2](v2026.10.28.2.md) (`c8f75a35`, server and runner)
- Range: `v2026.10.28.2..v2026.11.01.1`
- Release class: neither FS nor TL
  ([High-risk change release](../operations/high-risk-change-release.md)).
  The FS candidate paths `runner/src/runner-cli.ts`, `runner/src/supervisor.ts`
  and `runner/src/transport.ts` gain a handler that runs only when the server
  sends `observe_codex_work`, which only an operator-run maintenance script
  requests; the start path gains one UUID and one control-event entry. No
  `wrapper/` file changed. No SDK, CLI or native pin changed. The release
  touches authentication and authorization (bearer credentials), the server
  deploy CLI's persisted journal and manifest format, and the runner control
  channel join, so it goes through the operator's release card rather than
  the ordinary release path.

## Highlights

- **OAuth device authorization grant for native clients.** A native client
  such as kaoiro-client.nvim shows a code, a signed-in dashboard user approves
  it at `/device`, and the client receives a device access token that the
  server accepts as an `Authorization: Bearer` credential
  ([Server configuration](../reference/configuration/server.md#device-authorization-grant),
  [issue #801](https://github.com/sakuraiyuta/kaoiro/issues/801)).
- **Environment-consistency checks in the server deploy CLI.** The CLI checks
  persisted store paths against the old store identity, and records its
  evidence in a versioned journal and manifest format
  ([issue #920](https://github.com/sakuraiyuta/kaoiro/issues/920)).
- **Live grid order and grid card faces.** The operator can choose the live
  grid order, and clicking a grid card's face opens the agent detail
  (contributed in [#908](https://github.com/sakuraiyuta/kaoiro/pull/908) and
  [#909](https://github.com/sakuraiyuta/kaoiro/pull/909)).

## Changes

### Server

- Device authorization grant endpoints `/oauth/device`, `/oauth/token`,
  `/device`, `/session/device/lookup` and `/session/device/decision`. Pending
  authorizations live in memory only. Device access tokens are stateless,
  sliding 3 days and absolute 30 days. The grant is offered only over HTTPS,
  with a single backend, at least one OAuth provider, and the dashboard served;
  otherwise `/session/auth-methods` reports `device: false`
  ([ADR-0070](../adr/0070-device-authorization-grant.md),
  [issue #801](https://github.com/sakuraiyuta/kaoiro/issues/801)).
- Operator-only and authenticated routes resolve the role from a device
  access token as well as from the session cookie; a viewer bearer gets 403
  ([issue #801](https://github.com/sakuraiyuta/kaoiro/issues/801)).
- The runner control channel registers each joined runner and answers
  `observe_codex_work`, used by the Codex backend compatibility script to read
  a runner's Codex work. A runner registry replaced while the application
  runs refuses observation until the application restarts
  ([issue #910](https://github.com/sakuraiyuta/kaoiro/issues/910)).

### Server deploy

- Versioned environment evidence in the journal and manifest; the CLI reads
  both the versioned and the legacy form. New refusals when the target or old
  image's persistence manifest is unavailable, when an existing store's path
  does not match, or when a new store's admission conditions are not met. A
  warning when old default paths depend on the startup environment
  (`TMPDIR`, `TEMP`, `TMP`)
  ([issue #920](https://github.com/sakuraiyuta/kaoiro/issues/920)).
- Corrected recovery guidance for an existing-store refusal
  ([issue #695](https://github.com/sakuraiyuta/kaoiro/issues/695)).

### Runner

- The runner answers `observe_codex_work` from its Supervisor state without
  changing it ([issue #910](https://github.com/sakuraiyuta/kaoiro/issues/910)).

### Dashboard

- Device authorization approval view at `/device`
  ([issue #801](https://github.com/sakuraiyuta/kaoiro/issues/801)).

  ([#908](https://github.com/sakuraiyuta/kaoiro/pull/908),
  [#909](https://github.com/sakuraiyuta/kaoiro/pull/909)).
- Work capacity settings save only the edited key, so an untouched key keeps
  following the server environment
  ([issue #800](https://github.com/sakuraiyuta/kaoiro/issues/800)).
- The permission request input is shown expanded and larger, and the status

  [#907](https://github.com/sakuraiyuta/kaoiro/pull/907)).

## Operator steps

- No new environment variable and no new server store. The deploy CLI does
  not ask to accept a new store.
- The reverse proxy must pass `/oauth/device`, `/oauth/token`, `/device` and
  `/session/device/*` to the server, and set `x-forwarded-proto` for the
  HTTPS check, before native clients can sign in with the device grant.
- The deploy CLI of this release writes the versioned journal format, which
  the previous release's CLI refuses. Roll back with this release's CLI, from
  the repository checked out at this release; do not check out the previous
  release first.
- Rolling back to v2026.10.28.2 keeps the server starting. Native clients
  cannot connect while it runs, because that release does not accept bearer
  credentials; issued device access tokens work again after updating back.
