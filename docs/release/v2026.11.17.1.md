# Release v2026.11.17.1

- Previous production release: [v2026.11.16.1](v2026.11.16.1.md)
- Range: `v2026.11.16.1..v2026.11.17.1`
- Release class: FS
  ([High-risk change release](../operations/high-risk-change-release.md)).
  The FS path list catches `runner/src/runner-cli.ts`: the runner changes
  its environment at start, before it starts its first child, and the
  runner is on every engine's start path, so no engine is a standby for
  another. The TL path list catches nothing. No wrapper source reads the
  removed names, and a wrapper receives its own server token in its launch
  file. The range has no server, dashboard, wrapper, protocol, runner
  deploy script or tagging change, and no engine SDK, CLI or native pin
  change. The protocol version stays 0.

## Highlights

- **The runner keeps its server credential out of the processes it
  starts.** Wrappers, engine probes, engines and the tools an agent runs no
  longer inherit the runner's token
  ([issue #1169](https://github.com/sakuraiyuta/kaoiro/issues/1169)).

## Changes

### Runner

- Credential and child processes
  ([issue #1169](https://github.com/sakuraiyuta/kaoiro/issues/1169)): the
  runner reads `KAOIRO_RUNNER_TOKEN` once at start and removes it, together
  with `KAOIRO_RUNNER_TOKENS` and `KAOIRO_LAUNCHER_RUNNER_TOKENS`, from its
  own environment before it starts any child. Authentication, reconnection
  and configuration reload keep using the value read at start; changing the
  token still needs a runner restart
  ([Runner credential and child processes](
  ../reference/configuration/runner.md#runner-credential-and-child-processes)).
- `scripts/dev.sh` and `scripts/dogfood.sh` started from an agent's shell
  no longer find the runner token as a preset; they use `runner/runner.env`.

## Operator steps

- Update only the runner. The server and the dashboard have no change in
  this range and stay on v2026.11.16.1. While they do, the launch dialog
  reports that the host's build revision differs from the server's; that
  line is expected. This release requires no new server store, data
  migration, environment variable, configuration key, runner capability or
  persona-pack update.
- Treat the release as FS. Run the start gate (required for FS), then
  follow
  [Release and restore the fleet](
  ../operations/high-risk-change-release.md#4-release-and-restore-the-fleet).
  No agent is a standby; plan on the plain shell. The start gate uses a
  dummy token against a closed port, so it does not exercise
  authentication; the identity and connectivity checks after the restart
  do.
- After restoration, check that the first turn completes on each engine in
  use, and that the three names are absent from an agent's tool shell on
  each engine. The first line must print 0; the second is a positive
  control and must print 1 (`compgen` is a bash builtin, so a shell other
  than bash prints 0 for both and measures nothing). The lines print names
  only, never values:

  ```sh
  compgen -e | grep -cE '^KAOIRO_(RUNNER_TOKENS?|LAUNCHER_RUNNER_TOKENS)$'
  compgen -e | grep -c '^PATH$'
  ```

  A nonzero first line means a source outside the runner, such as a login
  shell profile or an engine's configuration, exports a name again; find
  that source before judging the release.

## Rollback

- Return the runner to v2026.11.16.1 with the ordinary same-native
  rollback. No state or format changes. Under the older runner, every
  child again inherits the runner's credential.

## Known limits

- This stops inheritance only. A process of the same OS user can still
  read the runner's env file and the runner's initial environment, and a
  value that a login shell profile or an engine's configuration exports
  again is outside the runner's reach.
- Authentication and reconnection against a real server, a completed turn
  on each engine, and the names in an agent's tool shell were not
  measured before the release; the automated test runs the real runner
  entry point against a local endpoint and records the environments of
  real child processes. These are checked after the release on
  [issue #1169](https://github.com/sakuraiyuta/kaoiro/issues/1169).
- The test checks one child for each way the runner builds a child
  environment. The Codex wrapper and the two `agy` probes are not checked
  one by one; they build their environment the same way as a checked
  child.
