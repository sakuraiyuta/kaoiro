# Release v2026.11.06.2

- Previous production release: [v2026.11.06.1](v2026.11.06.1.md)
- Range: `v2026.11.06.1..v2026.11.06.2`
- Release class: TL
  ([High-risk change release](../operations/high-risk-change-release.md)).
  `wrapper/antigravity/src/host.ts` and `wrapper/agent-common/src/inter_agent.ts`
  changed.

## Highlights

- **An input written after agy exits on its own is delivered once.** When the
  epoch has already exited, Antigravity starts one replacement epoch before
  the write instead of failing with `api_error`
  ([issue #602](https://github.com/sakuraiyuta/kaoiro/issues/602)).
- **An unconfirmed write is reported as `receipt_unknown`.** A write that was
  attempted without a confirmed receipt is not sent again, and the sender is
  told not to resend
  ([issue #602](https://github.com/sakuraiyuta/kaoiro/issues/602)).

## Changes

### Antigravity

- A wait for `close` after the child's `exit` is now bounded. A timer of
  `#closeGraceMs` per epoch destroys stdio on expiry, so close and shutdown no
  longer wait forever on an exited child.
- A turn spawns at most one replacement epoch. A replacement that is already
  dead before the write stops without writing, as `api_error`.

### Delivery and wrappers

- `receipt_unknown` is a new peer error
  ([Errors](../reference/inter-agent/errors.md)). Its guidance is part of the
  `send_to_agent` description on every engine.

## Operator steps

- Advance the server and the runner to the same revision. The server has no
  code change in this range.
- Release class TL: follow the runner stop and restore steps of the
  [High-risk change release](../operations/high-risk-change-release.md).
- No configuration, store, SDK, CLI or native pin change.

## Known limits

- A write to a recovery candidate that was attempted is still reported as not
  delivered, so a sender may resend it.
