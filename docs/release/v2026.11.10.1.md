# Release v2026.11.10.1

- Previous production release: [v2026.11.08.1](v2026.11.08.1.md)
- Range: `v2026.11.08.1..v2026.11.10.1`
- Release class: TL
  ([High-risk change release](../operations/high-risk-change-release.md)).
  The Claude Agent SDK pin changes, which no path rule catches, so the
  claude-code engine is affected. No file on the FS or TL path lists changes,
  and the runner declares no dependency on the SDK, so FS does not apply.

## Highlights

- **Claude Code peers run on Agent SDK 0.3.321**, which bundles Claude Code
  2.1.321 (previously 0.3.319 and 2.1.319). The model alias `fable` now
  resolves to `claude-fable-5-2` instead of `claude-fable-5-1`
  ([issue #1063](https://github.com/sakuraiyuta/kaoiro/issues/1063)).
- **The dashboard can be shown in English.** The language is chosen on the
  login screen or in the settings drawer (`Auto`, `日本語`, `English`). The
  default, `Auto`, follows the browser's language
  ([issue #269](https://github.com/sakuraiyuta/kaoiro/issues/269)).
- **Known regression:** a background command with a label of about 1,000
  characters or more loses its continuation proof. See
  [Known limits](#known-limits)
  ([issue #1068](https://github.com/sakuraiyuta/kaoiro/issues/1068)).

## Changes

### Claude Code

- The Agent SDK is 0.3.321 and the bundled CLI is 2.1.321. The changelog
  reads, the input-folding re-measurement, the catalog probe and the
  real-model turns are recorded in the
  [0.3.321 evidence](../evidence/claude/issue-1063/sdk-0.3.321-2026-11-10.md).
  These behaviour changes come from the vendor, not from kaoiro:
  - A peer whose model is the alias `fable` runs Claude Fable 5.2 after the
    update. A peer pinned to `claude-fable-5-2` or `claude-fable-5-1` keeps
    the model it names.
  - The model list has 14 rows, as on 0.3.319 measured the same day. The
    `claude-fable-5-1` row is now its own row, and `claude-fable-5-2` is
    carried by the `fable` row
    ([Claude model catalog](../reference/engines/claude-model-catalog.md)).
  - Background command notifications show the model only the start and end
    of a label over about 1,000 characters. This causes the regression in
    [Known limits](#known-limits).
  - Several Bash permission checks now prompt in cases that went through
    before (`cp` or `mv` into a directory, `cp` and `mv` spelled by a path),
    and the account email check refuses only a shell command that holds the
    account email and names a User-Agent.

### Dashboard

- The dashboard's own text is available in Japanese and English. The choice
  is stored in the browser with the other dashboard settings and repaints the
  page without a reload. Names, model names, wire values, server messages and
  agent text are shown as received. Four absolute date and time displays
  follow the UI language
  ([dashboard i18n](../reference/ui/i18n.md),
  [ADR-0071](../adr/0071-dashboard-i18n.md),
  [issue #269](https://github.com/sakuraiyuta/kaoiro/issues/269)).

### Documentation

- The [Agent SDK bump checklist](../contributing/agent-sdk-bump.md) re-pins
  every guard bound to the installed artifact by searching for the outgoing
  versions and hashes
  ([issue #1063](https://github.com/sakuraiyuta/kaoiro/issues/1063)).
- [Dashboard strings](../contributing/dashboard-strings.md) describes how to
  add dashboard text in both languages.
- The README and the branch table describe the `gh-pages` branch that
  publishes the website
  ([issue #1035](https://github.com/sakuraiyuta/kaoiro/issues/1035)).

## Operator steps

- Update the server and the runner to the same commit. The server change is
  the bundled dashboard only; the runner change is the Claude Agent SDK.
  Neither depends on the other, so the order is not forced.
- The release is TL. Run the start gate (recommended for TL), then follow
  [Release and restore the fleet](../operations/high-risk-change-release.md#4-release-and-restore-the-fleet).
  After restoration, check one turn on a Claude Code peer.
- No new environment variable, no new server store and no stored format
  change. The persona packs do not change.

## Rollback

- Roll the server and the runner back to v2026.11.08.1 with the usual
  procedures. The Claude Agent SDK returns to 0.3.319 with the runner
  release, and `fable` resolves to `claude-fable-5-1` again. The dashboard
  returns to Japanese only. The previous dashboard ignores a stored language
  choice and drops it when it saves a setting, so the choice may read as
  `Auto` after a later update. No state migration is involved.

## Known limits

- [Issue #1068](https://github.com/sakuraiyuta/kaoiro/issues/1068): when a
  background Bash command or a Monitor has a label (its `description`, or the
  command when there is none) of about 1,000 characters or more, the new CLI
  shortens the label in the notification, and kaoiro's continuation proof
  refuses the completion with `native_completion_unproved`. A kaoiro tool
  call in the turn that the notification starts is rejected with
  `unbound_tool_call`. The wrapper stays up and later turns run. The way
  around it is to keep the `description` of a background command short.
- The 0.3.321 evidence has no changelog for 2.1.320, which upstream did not
  publish, and marks 21 entries in the relevant categories (counted once per
  category) as not checked. That records the absence of a check, not the
  absence of an effect.
- The CLI's own migration of saved Fable 5.1 model picks to `fable` was not
  measured on a peer; an explicit `claude-fable-5-1` pin was measured to stay.
- The Codex part of [issue #1044](https://github.com/sakuraiyuta/kaoiro/issues/1044)
  is not in this release.
