# Release v2026.11.25.1

- Previous release: [v2026.11.23.1](v2026.11.23.1.md), for the server, the
  dashboard, the runner and the wrappers.
- This release updates the server, the dashboard, the runner and the
  wrappers to one tag.
- Release class: FS, all engines (the runner's deploy scripts change).
  [High-risk change release](../operations/high-risk-change-release.md)

The five units remove features the operator no longer uses
([issue #1246](https://github.com/sakuraiyuta/kaoiro/issues/1246)).
No setting has to be changed before the update.

## Codex work query and backend switching tools

The read-only query of the Codex work a runner holds and the retired
backend switching tools (`scripts/codex-backend-operator.mjs`,
`scripts/codex-backend-compatibility.mjs`) are removed, together with the
server's `observe_codex_work` request and the runner's reply. Codex runs on
`app-server` only, as before.
[Codex backend retirement](../operations/codex-backend-switch.md)
[Issue #1247](https://github.com/sakuraiyuta/kaoiro/issues/1247)

## Launch dialog

The launch dialog no longer shows a build identity warning when the runner
and the server report different or dirty revisions. The warning never
blocked a launch. The header and the agent detail still show versions.
[Issue #1248](https://github.com/sakuraiyuta/kaoiro/issues/1248)

## Rally and stall monitoring

The review-quagmire monitor is removed: the rally marker in the
conversation list, the stall notice and the rally threshold in the settings
drawer. The server no longer reads `KAOIRO_QUAGMIRE_RALLY_TURNS`,
`KAOIRO_QUAGMIRE_STALL_MS` or `KAOIRO_QUAGMIRE_SETTINGS_PATH`, and no longer
opens `quagmire_settings.dets`. The sample Compose file drops that path.
[Issue #1249](https://github.com/sakuraiyuta/kaoiro/issues/1249)

## Work limits

Work has no per-director or per-assignee limit any more. The limits on
nominations per director, nominations per assignee and active work per
assignee are removed, with their dashboard setting.
`KAOIRO_WORK_NOMINATED_PER_PRINCIPAL` and `KAOIRO_WORK_ACTIVE_PER_ASSIGNEE`
are no longer read. The store-wide record cap, the receipt caps and the link
cap stay, and a refusal still replies `work_capacity`.
[Work capacity](../reference/configuration/server.md#work-capacity)
[Issue #1253](https://github.com/sakuraiyuta/kaoiro/issues/1253)

## Codex state backup and restore

The runner updater no longer takes or restores a copy of the Codex home.
`--codex-home`, `--codex-backup-dir`, `--restore-codex-backup` and the
resume and recover inputs are removed, and the updater refuses them before
it changes anything. The updater and the switch still compare the Codex
native of the current release with the target, and refuse before stopping
the runner when they differ. Pass `--codex-native-change` to cross a native
change. A new native migrates the Codex home on its first start, so going
back across a native change can lose Codex conversations; keep a native pin
change in a release of its own.
[Codex native changes](../operations/runner-update-and-rollback.md#codex-native-changes)
[Issue #1259](https://github.com/sakuraiyuta/kaoiro/issues/1259)

The Codex native pin is unchanged in this release (0.170.0), so neither the
update nor a rollback crosses a native change.

## Documentation

The documentation was checked against the code. The README lists the four
engines, Grok Build included, and the Japanese and English interface;
SECURITY.md no longer describes `allowedTools` as a limit on what an operator
credential can do; errors in the operations runbooks are corrected.
[Issue #1262](https://github.com/sakuraiyuta/kaoiro/issues/1262)

The README now opens with a one-line introduction and the introduction film,
and the project site follows the corrected documentation.
[Issue #1267](https://github.com/sakuraiyuta/kaoiro/issues/1267)

## Upgrade and recovery

1. No configuration change is needed. The variables and saved values of
   the removed features may stay in place. This release ignores
   `KAOIRO_WORK_NOMINATED_PER_PRINCIPAL`, `KAOIRO_WORK_ACTIVE_PER_ASSIGNEE`,
   `KAOIRO_QUAGMIRE_RALLY_TURNS`, `KAOIRO_QUAGMIRE_STALL_MS` and
   `KAOIRO_QUAGMIRE_SETTINGS_PATH`, keeps the saved work capacity row in the
   work store, and leaves `quagmire_settings.dets` unopened. The previous
   release reads all of them again after a rollback.
2. Before the update, check that the runner holds no retained Codex state
   snapshot and no operation lock (`kaoiro-runner-codex-state.mjs protected`
   of the current release prints nothing). The previous release's updater
   refuses this release while it retains a snapshot.
3. Deploy the server and its dashboard first. No new persistence store is
   added, so `--accept-new-store` is not needed. Then reload every open
   dashboard tab: an old page that opens the settings drawer asks for the
   removed work settings.
4. Update the runner and the wrappers with the current release's updater
   and the published archive. Do not pass the removed Codex flags or
   `--codex-native-change`.
5. Check the runner's actual version, registration and connection before
   restoring agents. Restore the selected agents and check their sessions
   and wrapper versions, and one turn of each engine.

A runner rollback to the previous release is a same-native switch with the
guarded switch's `--rollback`.

[Server update and rollback](../operations/server-update-and-rollback.md)
[Runner update and rollback](../operations/runner-update-and-rollback.md)

## Known issues

Both were found while checking the documentation and are already present in
v2026.11.23.1; this release does not fix them.

- Antigravity agents send no session capabilities, so session reset,
  permission switching, the question dialog and model switching are expected
  to be unavailable for them (not yet confirmed on a live agent).
  [Issue #1263](https://github.com/sakuraiyuta/kaoiro/issues/1263)
- Antigravity's `local` approval allows six Git subcommands without
  inspecting their operands.
  [Issue #1264](https://github.com/sakuraiyuta/kaoiro/issues/1264)
