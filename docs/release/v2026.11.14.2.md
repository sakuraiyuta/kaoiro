# Release v2026.11.14.2

- Previous production release: [v2026.11.14.1](v2026.11.14.1.md)
- Range: `v2026.11.14.1..v2026.11.14.2`
- Release class: TL for Claude Code and Codex, not FS
  ([High-risk change release](../operations/high-risk-change-release.md)).
  Claude Code now waits for host-owned probe teardown before the wrapper
  finishes; Codex changes the text delivered during a running turn. The TL
  path list catches the Claude Code `host.ts` and `cli.ts` and the Codex
  `cli.ts`. No FS-listed file, tagging mechanism, engine SDK, CLI or native
  pin changes. The runner start path is unchanged.

## Highlights

- **Browser caching.** Versioned persona sprites receive a private one-year
  cache, and content-hashed dashboard assets receive a public one-year
  cache. Dashboard documents still revalidate so a reload can load the new
  release ([issue #1105](https://github.com/sakuraiyuta/kaoiro/issues/1105),
  [issue #1106](https://github.com/sakuraiyuta/kaoiro/issues/1106)).
- **Clearer instruction sends.** A pending send blocks another submit to
  that agent. A sent instruction with no reply is reported as delivery
  unconfirmed, with its text retained, instead of a raw timeout error
  ([issue #1107](https://github.com/sakuraiyuta/kaoiro/issues/1107)).
- **Wrapper lifecycle fixes.** Claude Code supervises its host-owned probe
  processes through shutdown, and Codex includes reply-authorization
  guidance with ticketed mid-turn input
  ([issue #762](https://github.com/sakuraiyuta/kaoiro/issues/762),
  [issue #551](https://github.com/sakuraiyuta/kaoiro/issues/551)).
- **Rollback uses verified bytes.** Destructive server rollback restores
  from a private staged copy of the verified archive
  ([issue #610](https://github.com/sakuraiyuta/kaoiro/issues/610)).

## Changes

### Dashboard and browser delivery

- Persona sprite responses earn `private, max-age=31536000, immutable` only
  when `?v=` matches the content hash of the bytes sent. Unversioned or
  mismatched URLs, the persona manifest and errors keep `private, no-store`.
  Requests reaching the server still require authentication and pack scope
  ([persona delivery](../reference/protocol/persona-delivery.md)).
- Cached sprites can remain available after logout or access revocation.
  Cache clearing at logout is not included. After a pack update, reload the
  dashboard to obtain new manifest URLs; an already cached old URL can keep
  showing its old image.
- `/assets/*` uses `public, max-age=31536000, immutable`; that directory is
  reserved for content-hashed build output. `index.html` and notification
  worker files use `no-cache`. Icons and the web app manifest retain their
  existing ETag policy, and disabling dashboard delivery still works
  ([server configuration](../reference/configuration/server.md)).
- The composer shows its sending state from upload through the reply and
  ignores repeated submits, including Ctrl+Enter, for that agent. A send
  while disconnected or before the channel joins is refused immediately.
  An unconfirmed-delivery notice stays with its agent until the next submit
  to that agent or the detail view closes. Check the transcript before
  resending; unconfirmed does not mean rejected
  ([UI contract](../reference/ui/design.md)).
- Room folder controls in the detail strip have a lilac rim and faint fill
  to remain visible on light surfaces.

### Wrappers

- On POSIX, Claude Code host probes run in their own process group. The
  wrapper aborts and waits for teardown before finishing, escalating from
  TERM to KILL after two seconds with a bounded final wait. The parent owns
  the probe's temporary working directory. The runner-owned catalog probe
  keeps its existing behavior; Windows process-tree termination is outside
  this fix
  ([Claude model catalog](../reference/engines/claude-model-catalog.md)).
- Codex ticketed mid-turn steer text now carries the existing guidance to
  copy both `in_reply_to` and `reply_ticket` from `reply_authorization`.
  A resumed session can replay an old tool lookup result; this sentence
  supplies current guidance without refreshing that history. Ticket rules,
  tool schemas and the wire protocol are unchanged
  ([reply basis](../reference/inter-agent/reply-basis.md)).

## Operator steps

- Update the server and runner to the same release, updating the server
  while the runner is stopped. This release requires no new server store,
  data migration, environment variable, Compose setting, runner capability
  or persona-pack update.
- Treat the release as TL for Claude Code and Codex. Run the start gate
  (recommended for TL), then follow
  [Release and restore the fleet](../operations/high-risk-change-release.md#4-release-and-restore-the-fleet).
  After restoration, check a turn on each affected engine in use.
- Reload open dashboard pages to load the composer changes and current
  sprite manifest. No browser-storage migration or clearing is required.
- Before a destructive server rollback, reserve free space under
  `backup_root` for one additional copy of the pre-deploy archive. The CLI
  verifies a private staged copy and checks its SHA-256 inside the restore
  helper container before stopping the server. A missing, unreadable or
  mismatched container hash refuses the rollback before stop. See
  [failure handling](../operations/server-update-and-rollback.md#44-failure-handling)
  and the [preconditions](../operations/server-update-and-rollback.md#42-preconditions).

## Rollback

- Return the server and runner to v2026.11.14.1 with the usual procedures.
  No new store format needs conversion. Reload dashboards to align their
  controls with the restored release.
- The new rollback CLI restores the staged verified bytes even if the
  original archive is replaced after staging. This adds a copy and a
  container hash check; large-archive duration was not measured. The staged
  copy and its parent directories remain trusted under the single-writer
  `backup_root` contract. Using the older CLI restores its older archive
  handling behavior.
- An older server's cache headers cannot recall responses already cached
  by browsers under this release. Previously cached sprites may persist
  after access is revoked; uncached requests still require authorization.

## Known limits

- Issues [#1105](https://github.com/sakuraiyuta/kaoiro/issues/1105) and
  [#1106](https://github.com/sakuraiyuta/kaoiro/issues/1106) retain
  `needs-verify` for deployed-browser checks. The browser measurements used
  Chromium with the real endpoint's headers replayed by a minimal server;
  they did not drive the deployed dashboard behind its reverse proxy.
- Issue [#1107](https://github.com/sakuraiyuta/kaoiro/issues/1107) retains
  `needs-verify`: check sending feedback, repeated Ctrl+Enter, immediate
  refusal while disconnected and, if encountered, the persistent
  unconfirmed-delivery notice in the real dashboard. The reason the original
  reply was delayed remains undetermined; server-side deduplication and
  queue controls are outside this fix.
- The rollback change has narrow real-container premise checks, but no
  end-to-end destructive rollback rehearsal against a live daemon. Other
  daemon privilege arrangements and real disk faults remain unmeasured.
