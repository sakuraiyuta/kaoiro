# Release v2026.11.20.1

- Previous production release: [v2026.11.19.2](v2026.11.19.2.md).
- Range: `v2026.11.19.2..v2026.11.20.1`.
- The tag includes this note and its release-index entry.
- Release class: FS + TL
  ([High-risk change release](../operations/high-risk-change-release.md)).
  This runner and wrapper rollout is limited to Linux x64 with glibc.
  Runtime on Darwin and musl was not tested for this release.

## Bundled runner and wrappers

The runner and all four wrappers ship as one JavaScript entry with a
manifest and platform-specific native libraries
([issue #1215](https://github.com/sakuraiyuta/kaoiro/issues/1215)).
The archive no longer ships Claude or Codex executables. A bundled
release needs the selected pin in the engine store for each managed
spawn and for the Claude catalog probe.

1. Use the verified physical updater from the **candidate archive** for
   the first update from the old layout. The old updater rejects the
   bundle. The source and candidate must have the same Codex native
   SHA-256. Before updating, check the runner configuration and which
   required pins are in the engine store. With a valid configuration file,
   the updater acquires enabled managed pins before stopping the
   runner. If the file is absent, it skips acquisition.
2. Keep the verified candidate archive and its digest for rollback.
   Returning to the previous layout requires the candidate's physical
   switch tool and a measured rollback target with the same Codex
   native SHA-256. Follow the
   [first bundle update runbook](../operations/runner-update-and-rollback.md#first-update-from-the-old-layout-to-the-bundle).
3. Switch, rollback and configuration reload do not acquire engine
   pins. If a pin is missing or you enable an engine after installing
   the bundle, follow
   [Re-acquire an engine pin](../operations/runner-update-and-rollback.md#re-acquire-an-engine-pin)
   before launching that engine.

## Claude Code fail-stop recovery

An admission or receipt-timeout fail-stop now aborts the SDK's Claude
CLI child. This can interrupt running work. The runner can relaunch the
wrapper after exit if the existing recovery checks allow it. The turn
watchdog keeps its existing fail-stop behavior. See
[Recovering a fail-stopped Claude wrapper](../reference/engines/claude-events.md#recovering-a-fail-stopped-claude-wrapper)
and [issue #1188](https://github.com/sakuraiyuta/kaoiro/issues/1188).

## Codex authentication mode

The runner uses explicit `codex.auth_mode` and stops invoking
`codex doctor` for automatic detection. Before updating a runner with
Codex enabled (including when `capabilities` is omitted), set
`codex.auth_mode` to `apikey` or `chatgpt`, and declare the actual
`codex.chatgpt_plan` for ChatGPT. With the mode unset, the
standard Codex catalog is empty and the runner logs a warning.
Declared `codex.extra_models` remain. See
[Runner configuration](../reference/configuration/runner.md#codex-configuration) and
[issue #1214](https://github.com/sakuraiyuta/kaoiro/issues/1214).

## Antigravity catalog refresh

Restart the runner or save its configuration again to refresh the
Antigravity catalog and CLI version when the Antigravity capability is
enabled. The two probes run independently. See
[Deployment troubleshooting](../operations/deployment-troubleshooting.md#antigravity-cli-agy-not-found-or-version-warnings)
and [issue #1213](https://github.com/sakuraiyuta/kaoiro/issues/1213).
