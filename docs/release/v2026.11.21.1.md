# Release v2026.11.21.1

- Previous server and dashboard release: [v2026.11.16.1](v2026.11.16.1.md).
- Previous runner and wrapper release: [v2026.11.20.1](v2026.11.20.1.md).
- This release brings the server, dashboard, runner and wrappers to one tag.
- Release class: FS + TL.
  [High-risk change release](../operations/high-risk-change-release.md)

## Runner and release archives

- Bundled wrapper launch commands now come from the runner's engine
  descriptors. Claude Code, Codex, Grok and Antigravity keep their existing
  launch arguments. [Issue #1221](https://github.com/sakuraiyuta/kaoiro/issues/1221)
- The release workflow publishes Linux x64 and Darwin arm64 runner archives
  and a SHA-256 sidecar for each. On Linux x64 with systemd, the new updater
  accepts an exact tag, checks the downloaded bytes against the sidecar and
  verifies the expected build version before placing or reusing the release.
  A runner that predates this updater uses the verified Linux archive with
  `--tarball` for its first upgrade.
  [Issue #1223](https://github.com/sakuraiyuta/kaoiro/issues/1223)

## Server and dashboard

- The server accepts external engine declarations scoped to a runner host and
  records the engine that it authorized at launch. An external engine cannot
  set the permission controls reserved for bundled engines.
  [Issue #1225](https://github.com/sakuraiyuta/kaoiro/issues/1225)
- The operator and admin views retain the recorded external engine on a live
  disconnect and in a newly opened dashboard. This lets the dashboard apply
  the host's current declaration before offering or sending an action. The
  bundled engines keep their existing choices, defaults and limits.
  [Issue #1231](https://github.com/sakuraiyuta/kaoiro/issues/1231)
  [Issue #1229](https://github.com/sakuraiyuta/kaoiro/issues/1229)

## Optional local external engines

An operator can configure a trusted local command in the runner's optional
`external_engines` array. The runner reads the engine's declaration at startup.
Changing the command or repairing a failed discovery requires a restart. An
invalid engine entry is reported and omitted while the rest of the runner
starts. Each host controls its own commands. A runner with no external entries
uses only the bundled engines.
[Runner configuration](../reference/configuration/runner.md#external-engines)
[Issue #1234](https://github.com/sakuraiyuta/kaoiro/issues/1234)

## Upgrade and recovery

1. Prepare the server and runner rollback targets and verify the published
   archive against the digest recorded for this release.
2. Deploy the receiving server and its dashboard first. Confirm health and
   existing runner connectivity, then update the runner and wrappers from
   the verified archive.
3. Check the runner's actual version, registration and connectivity before
   restoring agents. Inspect the offline list and restore the selected agents
   individually. Check their returned sessions and wrapper versions.
4. Start with bundled engines. Schedule any external configuration after the
   coordinated rollout has passed its checks. If rolling back after enabling
   external engines, stop those agents and restart the runner with bundled
   capabilities before restoring the earlier server.
