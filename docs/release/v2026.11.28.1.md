# Release v2026.11.28.1

- Previous release: [v2026.11.26.1](v2026.11.26.1.md), for the server, the
  dashboard, the runner and the wrappers.
- This release updates the server, the dashboard, the runner and the
  wrappers to one tag.
- Release class: high risk, FS and TL for all engines. The runner's startup
  path changes, and so do the turn paths of Claude Code and Codex and the
  shared wrapper code. Follow the
  [high-risk release procedure](../operations/high-risk-change-release.md).

This is the second batch of removing features the operator no longer needs
([issue #1280](https://github.com/sakuraiyuta/kaoiro/issues/1280)).
No setting has to be changed before the update.

## Runner configuration takes effect at restart

Saving `runner.config.json` leaves the active host configuration in effect,
including its allowed directories, permission ceilings, model declarations
and settings used by new or relaunched wrappers. The journal reports the
restart rule at startup and on the first observed save. Antigravity's model
list and CLI version are probed at startup. Saving identical bytes no longer
requests a probe.

Keep the last working config and drain work on the host before restarting.
Stopping the runner stops all supervised agents. Muse loses its per-child
recovery checkpoint, so the next prompt to each Muse agent carries its
persona again. Verify the new registration and the changed setting, then
restore the intended agents explicitly. If startup fails, restore the last
working file before restarting. Rolling back to the previous runner with a
valid config restores its save behavior.
[Applying host configuration](../reference/configuration/runner.md#applying-host-configuration)
[Issue #1287](https://github.com/sakuraiyuta/kaoiro/issues/1287)

## Per-agent checklist view

The dashboard no longer shows each agent's expandable checklist, completion
counter or item details. Claude Code and Codex wrappers stop collecting the
checklist for kaoiro. Native planning, Codex plan mode, Muse plan logs and
the child-task ring remain available.
[ADR-0079](../adr/0079-retire-agent-checklist-projection.md)
[Issue #1284](https://github.com/sakuraiyuta/kaoiro/issues/1284)

The wire protocol version stays `"0"` for this retirement, by operator
decision. The server still accepts the reserved legacy checklist pair from
older wrappers, then acknowledges and discards it. The dashboard ignores the
pair from an older server.
[Version exception](../reference/protocol/versioning.md#retired-checklist-projection)

The server and dashboard can be updated before or after the runner and its
wrappers. An old tab connected to the old server can retain its checklist
until it reloads or rejoins. Rolling back both sides restores collection
when native planning events arrive.

A valid checklist received from an older wrapper still carries session
identity for restore. New wrappers carry the ID on their next ordinary
outbound frame. A wrapper that stops first may restore the previous session.
[Issue #1282](https://github.com/sakuraiyuta/kaoiro/issues/1282)

## Server dependencies

Phoenix is updated to 1.8.17, Plug to 1.20.4 and Phoenix PubSub to 2.4.1 to
address three published security advisories. The update ships in the server
image; it needs no runner or wrapper change.
[Issue #1283](https://github.com/sakuraiyuta/kaoiro/issues/1283)

## Internal changes

These keep behavior.

- Claude Code and Codex share one active-turn watchdog.
  [Issue #1285](https://github.com/sakuraiyuta/kaoiro/issues/1285)
- Grok and Muse share the ACP session page walker in the runner.
  [Issue #1286](https://github.com/sakuraiyuta/kaoiro/issues/1286)
- Unused internal exports, duplicated contracts and redundant tests are
  removed. [Issue #1281](https://github.com/sakuraiyuta/kaoiro/issues/1281)

## Upgrade and recovery

1. Follow the high-risk release procedure for both FS and TL, including
   the production-shape start gate and fleet restoration checks.
2. The new runner reads the configuration file on disk at startup,
   including an edit that the old runner's reload rejected. The start gate
   checks that file.
3. The server update rebuilds the image with the new dependencies.
4. Reload dashboard tabs after the server update.
