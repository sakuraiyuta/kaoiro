# Release v2026.11.14.1

- Previous production release: [v2026.11.10.3](v2026.11.10.3.md)
- Range: `v2026.11.10.3..v2026.11.14.1`
- Release class: ordinary, neither FS nor TL
  ([High-risk change release](../operations/high-risk-change-release.md)).
  The changes are confined to the dashboard and documentation. No runner,
  wrapper, server logic, protocol, engine SDK, CLI or native pin changes.

## Highlights

- **Clean up one room.** An operator can open a confirmation from a room's
  grid separator to close its conversations and clear its connected agents'
  sessions ([issue #1101](https://github.com/sakuraiyuta/kaoiro/issues/1101)).
- **Fold room groups in the detail header.** Folder buttons reveal each
  room's agent chips; a closed folder shows the live-member count and a state
  lamp ([issue #1093](https://github.com/sakuraiyuta/kaoiro/issues/1093)).
- **Keep a room order in this browser.** Up/down buttons reorder the rooms,
  including the lobby, without changing memberships or other devices
  ([PR #1096](https://github.com/sakuraiyuta/kaoiro/pull/1096)).

## Changes

### Dashboard

- The detail strip groups chips by room, prints the room name below them,
  and follows the grid's room order. Empty groups are omitted. Desktop chips
  wrap, and narrow screens keep horizontal scrolling
  ([PR #1095](https://github.com/sakuraiyuta/kaoiro/pull/1095),
  [room display contract](../reference/ui/design.md#rooms-in-the-grid)).
- Only the selected agent's room starts open. Switching agents opens the
  destination without closing other rooms; manual closure survives state
  updates and reconnects when membership is unchanged. Open/closed state
  lasts for the detail visit only. A lone lobby without unconfirmed members
  stays open without a folder control. Hidden chips cannot receive focus;
  reduced-motion preferences disable the reveal transition.
- A closed folder's lamp prioritizes permission/question/input waiting,
  error, active work, done/idle, then disconnected. Its accessible name
  includes the room, count and state in Japanese or English.
- Room ordering is available to operators and viewers on confirmed room
  separators. The grid, offline section, detail strip and previous/next
  navigation follow it. The preference is saved as room IDs under
  `kaoiro.roomOrder.v1` in localStorage. Unknown IDs are ignored; rooms absent
  from the saved list follow in server order.
- Room cleanup names the room and counts the proposed conversations and
  connected agents before confirmation. It includes only open conversations
  whose participants all belong to that room. It freezes the IDs and checks
  the target sets again before sending; a detected change or incomplete
  information prevents execution. Cancel sends no cleanup requests. Empty
  confirmed rooms remain available in the operator's grid. The existing
  global cleanup remains available in settings.
- Main content now reserves bottom space using the sheet handle's safe-area
  offset, and the agent name is centered in the detail panel whether or not
  its rename control is shown
  ([PR #1094](https://github.com/sakuraiyuta/kaoiro/pull/1094),
  [PR #1097](https://github.com/sakuraiyuta/kaoiro/pull/1097)).

## Operator steps

- Use the ordinary update procedure. This release needs no new server store,
  data migration, environment variable, Compose setting, runner capability
  or persona-pack update.
- Reload open dashboard pages after the update to load the new controls.
  Previously loaded pages retain their old presentation and remain compatible
  with the unchanged server protocol.
- No browser-storage migration or clearing is required. Room ordering is a
  preference for this browser origin, not a server setting or a cross-device
  preference. If storage is unavailable, ordering still works for the page.
- For a non-destructive smoke check, open a room's cleanup confirmation,
  check its room name and two counts, then cancel. Do not execute cleanup
  merely to validate the release: it closes conversations and clears sessions.

## Rollback

- Use the usual rollback procedure to return to v2026.11.10.3. The server's
  storage formats and communication contracts are unchanged. The older
  dashboard ignores `kaoiro.roomOrder.v1` and uses its original order; the
  saved order remains available when returning to this release.
- A page already loaded from this release can still use the existing server
  commands after a server rollback, including room cleanup. Reload open
  dashboards to align their presentation with the restored release.
- A code rollback does not undo cleanup already accepted by the server or
  wrappers. Server archive restoration has its usual data-loss implications;
  do not treat it as an undo operation for cleanup.

## Known limits

- Room cleanup depends on the browser's room snapshot. If an update is
  delayed or never arrives, the last comparison can use stale membership.
- Membership can change after the final comparison and before the server
  handles a request. Cleanup is not an atomic room operation, so requests
  can reach members after they move. Both limits are stated in the
  confirmation and the [UI contract](../reference/ui/design.md#rooms-in-the-grid).
- This release preparation did not repeat mixed-version live-server tests
  or destructive cleanup in production. Compatibility above follows from
  the unchanged server/protocol code and the separate browser preference.
  Physical-device safe-area behavior and screen-reader output were not
  re-measured during release preparation.
