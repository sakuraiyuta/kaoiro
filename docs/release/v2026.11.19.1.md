# Release v2026.11.19.1

- Previous production release: [v2026.11.18.1](v2026.11.18.1.md).
- Range: `v2026.11.18.1..v2026.11.19.1`.
- Tag and note location: see the [release record](#tag-and-note-location).
- Release class: FS + TL, all engines
  ([High-risk change release](../operations/high-risk-change-release.md)).
  The runner entry, launcher, launch shim and verifier change, as do the
  argument parser and the start modules of all four bundled wrappers.
  The protocol version stays 0. No engine SDK, CLI or native pin changes.

## Tag and note location

For v2026.11.19.1 only, the operator approved the tag on the released code
commit, `444cff9b29ec475cdf2464908f5bff262797cf28`, with this note on
develop. The note lands before the tag is created, but is absent from the
tag's tree. This keeps the release separate from later distribution work
already on develop. The exception changes only this note's placement.

## Highlights

- One entry starts the runner, setup wizard and wrappers
  ([issue #1177](https://github.com/sakuraiyuta/kaoiro/issues/1177)).
- Initial prompts and resume targets travel in the private launch file,
  rather than the wrapper process's arguments.
- Wrapper modules no longer start themselves when imported
  ([issue #1178](https://github.com/sakuraiyuta/kaoiro/issues/1178)).

## Changes

- Use `node runner/dist/kaoiro.js runner [config]` for a manual runner,
  `node runner/dist/kaoiro.js setup` for setup, and
  `node runner/dist/kaoiro.js wrapper <engine> run <launch file>` for a
  manual wrapper. The entry also accepts `--version [--json]` and
  `wrapper claude-code probe`. Unknown engines, verbs and invalid wrapper
  argument shapes print usage and exit 64 before connecting.
- A launch file carries `initial_prompt` and `resume_session_id`.
  The positional prompt and `--resume` form are removed. Relaunching a
  wrapper still does not resend the initial prompt. The runner creates
  these fields automatically for an ordinary dashboard launch.
- Children start from the physical path of the entry that started their
  parent. Moving `current` does not move a running runner's next wrapper
  to another release.
- Wrapper hot reload and the `KAOIRO_WRAPPER_DEV` branch are removed.
  Rebuild wrappers and restart agents to apply wrapper source changes.
  The wrapper workspace's `dev` script is removed; `demo` uses the entry.
- The Agent SDK bump procedure now has a standing design and a fold
  premise harness
  ([issue #1168](https://github.com/sakuraiyuta/kaoiro/issues/1168),
  [issue #1184](https://github.com/sakuraiyuta/kaoiro/issues/1184)).
  This release does not bump the SDK.

## Operator steps

- Update the runner and its bundled wrappers. The server and dashboard
  stay on v2026.11.16.1: their executable code has no change in this range.
  The launch dialog continues to show a host/server build-revision
  mismatch. Check machine identities and dirty flags directly.
- Follow the FS + TL start gate and fleet restoration procedure. No
  engine is a standby for another; retain a plain-shell recovery path.
  Before release, rerun the real-engine launch checks, the symlink and
  service launch checks, and install/switch/rollback with both releases'
  tools on the final tagged artifacts. Use no `--allow-dirty` override.
- A service using `deploy/kaoiro-runner-launch.sh` needs no unit change.
  A custom service or manual command that directly starts `dist/cli.js`
  must use the entry or the launch shim instead.
- No runner configuration migration, server store, capability change,
  engine store or Codex state migration is required. This release keeps
  the existing release layout and engines inside the release tree.
- After restoration, check connection, identity and the first completed
  turn for every engine in use. Bulk restoration does not exercise a
  brand-new agent's initial-prompt path.

## Rollback

Return the runner and wrappers to v2026.11.18.1 with the ordinary
same-native guarded rollback. The server stays on v2026.11.16.1, so its
build-revision mismatch notice remains. The prior runner already removes
its credential variables from child environments; rollback retains that
fix. Record the release IDs that `current` and `previous` point to before
updating. Run rollback from the verified physical directory of the tool
release, rather than selecting tools through a link that may have moved.

## Known limits

- The updater with this exact candidate is first exercised during the
  production update. Pre-release checks cover real install, switch,
  rollback and launch paths, rather than a full updater/service run.
- If a release loses both `dist/kaoiro.js` and its manifest line, install
  and switch do not reject it; its launch shim stops with exit 78
  ([ADR-0076](../adr/0076-single-kaoiro-entry-point.md)). Removing only
  the entry file is rejected by the verifier.
- Launch-file removal after a forced kill or operating-system failure is
  not guaranteed. Files normally use mode 0600 in a private directory.
- The whole Node `execArgv` is passed to children, including debugging
  options. The production shim passes none. Do not delete the release
  directory of a running runner; later wrapper starts still need it.
- Engine acquisition, the shared engine store, and Codex/Antigravity
  bridge or hook subcommands are later units. The Claude probe's direct
  entry remains in this release; its retirement is separate.
