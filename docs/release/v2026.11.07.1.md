# Release v2026.11.07.1

- Previous production release: [v2026.11.06.2](v2026.11.06.2.md)
- Range: `v2026.11.06.2..v2026.11.07.1`
- Release class: FS and TL
  ([High-risk change release](../operations/high-risk-change-release.md)).
  `runner/src/supervisor.ts`, `runner/src/spawn.ts`, `runner/src/config.ts`,
  `runner/src/runner-cli.ts`, `runner/src/delivery-settings.ts`,
  `wrapper/core/src/recovery_checkpoint.ts` and the `host.ts` and `cli.ts` of
  every wrapper changed.

## Highlights

- **The Codex exec backend is retired.** `codex.backend: exec` is refused at
  runner start, at reload and in direct wrapper configuration. Omitted or
  `app-server` is the only accepted selection
  ([issue #1008](https://github.com/sakuraiyuta/kaoiro/issues/1008)).
- **Crash recovery follows a launch-owned checkpoint.** After an unexpected
  wrapper exit, the runner resumes the session recorded for that launch instead
  of starting from the server pointer
  ([issue #524](https://github.com/sakuraiyuta/kaoiro/issues/524)).
- **Retired delivery inputs are gone.** The in-flight environment variables and
  lists, `codex.operator_steer` and `claude_code.phase2_delivery` are no longer
  read and no longer warn
  ([issue #566](https://github.com/sakuraiyuta/kaoiro/issues/566)).
- **Dashboard notifications reach Android.** Hand-wait notifications fall back
  to a service worker when the page-level constructor is rejected
  ([issue #691](https://github.com/sakuraiyuta/kaoiro/issues/691)).

## Changes

### Recovery

- Each wrapper launch writes a private checkpoint. An unexpected exit selects
  from it, within the existing retry cap and without replaying the initial
  prompt. See the
  [runner control reference](../reference/protocol/runner-control.md).
- A watchdog stop or a binding conflict now stays down. Recover with restore or
  an offline `resume_session`.
- A plain restart reads the checkpoint before it kills anything. When recovery
  is refused it fails with `restart recovery refused` and leaves the child
  running; choose switch, reset, restore or stop.
- A checkpoint write failure exits the wrapper with code 79, and the runner
  logs `recovery refused` with `checkpoint_unavailable`.

### Codex

- The exec runtime, its test seam and the unused SDK patch are removed. The
  `@openai/codex-sdk` version does not change
  ([issue #1008](https://github.com/sakuraiyuta/kaoiro/issues/1008)).
- Exec preparation, `pin-exec-fresh`, `restore-fresh --backend exec` and exec
  restore observation are refused. API-key authentication with app-server stays
  unmeasured, as described in the
  [migration runbook](../operations/codex-backend-switch.md#exec-retirement).

### Delivery and wrappers

- A Claude peer whose context window is full is reported as such, not as
  `rate_limit`, and observed quota errors reach peers
  ([issue #522](https://github.com/sakuraiyuta/kaoiro/issues/522)).
- A Claude host that is closing no longer dispatches the next queued input
  ([issue #527](https://github.com/sakuraiyuta/kaoiro/issues/527)).
- Grok adopts historical permission evidence from a revision-zero sync
  ([issue #676](https://github.com/sakuraiyuta/kaoiro/issues/676)).
- The Antigravity gate classifies `read_file`
  ([issue #699](https://github.com/sakuraiyuta/kaoiro/issues/699)).

### Dashboard and server

- The server serves `notification-worker` as a static path for the Android
  fallback ([issue #691](https://github.com/sakuraiyuta/kaoiro/issues/691)).
- While a permission observation is unknown, the last effective values appear
  in an explicitly historical row
  ([issue #614](https://github.com/sakuraiyuta/kaoiro/issues/614)).

### Deploy

- Source checks ignore local worklogs, so a clean deploy checkout is not
  reported as dirty
  ([issue #583](https://github.com/sakuraiyuta/kaoiro/issues/583)).

## Operator steps

- This release must deploy server and runner together. **Stop every runner
  before the server commit** and follow
  [Coordinated server and wrapper updates](../operations/runner-update-and-rollback.md#coordinated-server-and-wrapper-updates).
  Then use the start gate and bulk restoration from
  [High-risk change release](../operations/high-risk-change-release.md).
- **Before this release:** remove `codex.operator_steer` and
  `claude_code.phase2_delivery` from each runner config, restart on the current
  release and confirm that the retirement warning count is 0. This release does
  not warn, so a count taken after it proves nothing. The removal ends the
  rollback window of
  [issue #565](https://github.com/sakuraiyuta/kaoiro/issues/565).
- **Codex:** an explicit `codex.backend: exec` stops the whole runner at start,
  for every engine. Move such a host to app-server first with the
  [migration runbook](../operations/codex-backend-switch.md). Before installing
  this release, retain and identify the last pre-retirement release artifact
  and its native pin.
- No new environment variable, no new server store and no stored format change.

## Rollback

- The fallback for an app-server failure is a code rollback to the last release
  before exec retirement, plus `pin-exec-fresh` and a fresh exec restart.
  **Context is lost.** Returning to old code alone does not select exec. Follow
  the [migration runbook](../operations/codex-backend-switch.md#exec-retirement).

## Known limits

- A crash right before a block record is renamed can relaunch once from the
  previous record. The retry cap bounds it.
- The Android fallback is not yet confirmed on a device
  ([issue #691](https://github.com/sakuraiyuta/kaoiro/issues/691)).
- `tsx watch` and restarts of the runner itself are out of scope of the
  checkpoint ([issue #530](https://github.com/sakuraiyuta/kaoiro/issues/530)).
