はじめかた

engine ごとの契約から、最初の agent が画面に現れるまでと、その後の運用の流れ。

01 / 全体

使い始めるまでの順序

セキュリティ。operator の認証情報を持つ人は、agent が動く全ての machine で command を実行できます。それらの host への SSH 鍵と同じように扱い、先に SECURITY.md を読んでください。

  1. 使う engine ごとに契約を用意する
  2. host を用意する
  3. server を入れる
  4. agent を動かす host ごとに runner を入れる
  5. 最初の agent を起動する
  6. 日々の運用

このページは地図です。command とその正確な順序は repo の docs (英語) にあり、このページと docs が違うときは docs が正です。production manual から始めてください。

02 / 契約

engine ごとの契約と認証

各 engine の利用には、各社との契約が要ります。各 engine は、agent の host の上で、それぞれの CLI か SDK で login します。

各サービスの規約を確認してください。プランと規約は変わります。kaoiro から engine を使う前に、各社の規約・利用条件を読んでください。

03 / host

host を用意する

server を動かす machine と、agent を動かす machine を決めます。同じ machine でも構いません (例 B)。

  • server の host

    Docker Engine と Docker Compose plugin、Elixir ~> 1.15 と Phoenix、deploy CLI 用の Node.js 22 以上。

  • agent の host

    Node.js 22 以上と、そこで動かす各 engine の CLI。Linux では runner を systemd の user unit で動かします。macOS での運用は まだ検証していません。

  • server への届き方

    .env を書く前に決めます。既定は nginx の reverse proxy の後ろの 127.0.0.1 で、VPN の中の直接の address も選べます。

  • SSH

    server の host と全ての runner の host に SSH で入れ、各 host の鍵を確認済みにしておきます。

全部の一覧: Server install runbook の Prerequisites。

04 / server

server を入れる

  1. server の host で、動かす commit を指定して repo を clone します。
  2. server/ で mix kaoiro.env を実行します。.env を書き、SECRET_KEY_BASE と client・runner の token を作り、公開する host 名を尋ねます。表示された runner の token は、runner を入れるときに使います。
  3. checkout の root で node server/deploy/kaoiro-server-deploy.mjs start --initialize を実行して起動します。
  4. network and login runbook に従って reverse proxy か VPN の address を設定します。必要なら Google、GitHub、Nextcloud の login も足せます。

詳しくは Server install runbook と production manual の 1 節。

05 / runner

agent の host ごとに runner を入れる

  1. host の OS と CPU に合う runner の tarball を作り、host に写します。
  2. 展開した tarball から kaoiro-runner-bootstrap.sh を実行します。対話は最初の wizard だけで、その後 runner を入れて service として起動します。
  3. Linux では、login しなくても起動時に runner が動くよう、その user の linger を有効にします。
  4. 各 engine の CLI を host に入れ、runner を動かす user で login しておきます。本番の Codex は専用の home directory を使います。Codex home for production を見てください。

詳しくは Runner install and distribution と production manual の 2 節。結果は 3 節の Verify で確かめます。

06 / 起動

最初の agent を起動する

  • login

    dashboard を開き、client の token か、設定した login で入ります。

  • 起動

    host、persona、engine、作業 directory、権限のモードを選んで起動します。作業 directory は runner が許可したものに限られます。

  • 見守って応える

    agent はキャラクターのカードとして現れます。承認待ちの tool call は browser に届くので、そこで応えます。

07 / 日々

日々の運用

  • 承認と通知

    agent が操作を返したら、デスクトップ通知と状態ごとの音で知らせます。dashboard は phone の幅まで縮むので、席を離れていても応えられます。

  • 更新と rollback

    server と runner の更新には決まった順序があります。production manual の 4 節 に従い、戻すときは 5 節 を使います。runner を再起動すると、その下の agent は全部止まります。

  • 困ったとき

    deployment troubleshooting から始めてください。

  • リリースノート

    release ごとの変更は リリースノート にあります。
