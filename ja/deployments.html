kaoiro / 構築事例

構築事例

3 つの構成の例です。host 名は別名で、オフラインの例は今は動かせない将来の構想です。

01 / 例 A

自前のオンプレで、役割ごとに host を分ける

作者が毎日使っている構成です。host 名は別名にしてあります。server、agent、重い試験に、それぞれ別の machine を割り当てています。

  • server-host

    Linux の 1 台。kaoiro server を Docker Compose で動かし、HTTPS の reverse proxy の後ろに置いて、インターネットから届くようにしています。

  • agent-host

    Linux の 1 台。runner を systemd の user unit で常駐させ、この 1 台で十数人の agent を動かしています。内訳はおよそ Claude Code 6、Codex 4、Antigravity 2、Grok Build 1 です。

  • test-host

    重い試験を隔離した container で回す別の machine です。作者の運用の工夫で、kaoiro の機能ではありません。

  • client と file

    operator は PC と phone の browser で dashboard を使います。operator が読む file は、自前の Nextcloud で受け渡しています。これも kaoiro の外の仕組みです。

この構成での各 engine の契約

enginekaoiro からの使い方この構成の契約
Claude CodeClaude Agent SDKClaude Ultra
CodexCodex app-serverChatGPT Pro
AntigravityAntigravity CLIGoogle AI Pro
Grok Build常駐する 1 つの ACP sessionSuperGrok

プランと規約は変わります。各社が文書にしている内容は はじめかた にまとめました。operator の認証情報を持つ人は agent-host で command を実行できます。server を外に出す前に SECURITY.md を読んでください。

02 / 例 B

1 台にすべてを載せる

個人で使うなら、server、runner、agent を 1 台に載せられます。手順は複数 host のときと同じ runbook を、1 台の上でたどります。

  • 動くもの

    1 台で、Docker Compose の server、runner、起動した agent が動きます。server は既定で 127.0.0.1:4000 だけに bind し、同じ host の reverse proxy がそこへ届きます。

  • phone から応答するなら

    .env を書く前に、server への届き方を決めます。HTTPS の reverse proxy か、VPN の中の直接の address です。VPN の方式は、公開のインターネットに決して出しません。どちらも network and login runbook (英語) にあります。

  • まず試すなら

    README の Quick start (英語) は、./scripts/dev.sh で全部の層を 1 台で、hot reload つきで起動します。日々使うなら production manual (英語) に従ってください。

  • 気をつけること

    runner を再起動すると、その下の agent は全部止まります。1 台の構成では、動かしている agent が全部その runner の下にいます。

03 / 例 C

イントラネットだけで動かす: 将来の構想

今は動かせません。kaoiro はまだローカルの AI エージェントに対応していません。この節は、対応した場合にどう動きうるかの構想です。これを前提に導入を計画しないでください。

Claude Code、Codex、Antigravity、Grok Build は、どれも各社のクラウドのサービスを使います。そのため今の kaoiro は、インターネットから切り離しては動きません。

  • 何が変わる必要があるか

    自分の機材で model を動かす engine です。issue 1043 は engine の pluggable 化を提案しています。source に足すのでなく、公開の protocol で外付けの engine をつなげるようにする案です。open の提案で、出る時期は決まっていません。

  • 中に閉じられるもの

    server、runner、dashboard は、今も自分の machine で動きます。そうした engine があれば、原理的には全体をイントラネットの中に閉じられます。
